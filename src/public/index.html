Ledger Financial Architecture

This system handles banking-grade transaction mechanics, implementing ACID compliance, strict immutability, and double-entry bookkeeping.

📊 Double-Entry Ledger Bookkeeping

All account balances are computed dynamically by summing historical ledger entries. The database contains no direct "balance" variable. Instead, a transfer creates two immutable records simultaneously: a DEBIT from the sender and a CREDIT to the recipient.

🔒 Atomic 10-Step Transfer Flow

Money movements utilize MongoDB transactions session handlers. The lifecycle ensures data consistency:

  • 1. Request Validation
  • 2. Idempotency Key validation
  • 3. Verify Account status (ACTIVE)
  • 4. Aggregate Sender Balance
  • 5. Create Transaction record (PENDING)
  • 6. Create Debit entry & insert into Ledger
  • 7. Create Credit entry & insert into Ledger
  • 8. Mark Transaction COMPLETED
  • 9. Commit Session Transaction
  • 10. Send Confirmation Email
⚡ Idempotency Shielding

Double submissions, network drops, or retries are neutralized by requiring an idempotencyKey. If the server detects a repeated key, it returns the existing record immediately without duplicating calculations or debits.

📖 Developer Guide & Setup Guide

Backend Ledger is a solid, scalable financial transaction ledger. Below are instructions to run, configure, and demonstrate the project locally.

Prerequisites

  • Node.js (v16+) installed.
  • MongoDB running locally at mongodb://localhost:27017 or a remote MongoDB cluster.

1. Install Dependencies

Run the package manager in the project root directory to install necessary dependencies:

npm install

2. Environment Variables (.env)

A .env file has been set up with default development credentials. Verify it matches your configuration:

MONGO_URI=mongodb://localhost:27017/backend_ledger
JWT_SECRET=e1CS7JH5w9uJz0l37PT3A8

Note: Gmail configurations can be added for SMTP operations, but if missing, the backend will catch transporter connections gracefully so you can still perform transfers without issues.

3. Run the Server

Start the nodemon-powered hot reload server:

npm run dev

Or start in normal production mode:

npm start

4. Interactive Demonstration (This Website)

Once running, open your web browser and navigate to:

http://localhost:3000/

You can use this interactive dashboard to simulate the backend client! Register users, create ledger entries, check dynamic balances, and view JSON payloads in real time.
